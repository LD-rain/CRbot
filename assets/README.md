# 按钮模板素材

## 目录

```
assets/
  screens/      ← 原始截图（留档，补模板时用）
  templates/    ← 程序实际读取的模板（构建时复制到 exe 旁边）
```

## 模板清单

| 文件 | 对应按钮 | 说明 |
|---|---|---|
| `btn_battle.png` | 主界面「对战」 | 普通外观（只有"对战"两字） |
| `btn_battle2.png` | 主界面「对战」 | 带"每日额外奖励"小字 |
| `btn_battle3.png` | 主界面「对战」 | 带皇冠计数 `0/500` 与倒计时 → 需要 `.mask` |
| `btn_join.png` | 主界面「加入」 | 免费模式的绿色按钮（加入 + 免费） |
| `btn_ok.png` | 结算页「确定」 | 蓝色按钮 |
| `btn_mode_1v1.png` | 模式菜单「经典1对1」 | 整行，含国王像和交叉剑图标 |
| `btn_mode_icon.png` | 主界面「当前模式」图标 | 命中说明已经在 1v1 → 跳过模式菜单，需要 `.mask` |

## 掩膜（`.mask`）

有些按钮上会有**每帧都不一样**的内容：`0/500` 的计数会一路涨到 500、倒计时会归零、
模式图标右上角的红点角标里还可能有白色数字。

这些区域用同名 `.mask` 文件标出来，**完全不参与**匹配计算：

```
# 每行一个矩形：x y w h（模板坐标），# 开头是注释
0 84 241 57      # btn_battle3.png.mask：忽略底部整条（计数 + 倒计时）
52 0 25 23       # btn_mode_icon.png.mask：忽略右上角红点角标
```

于是同一份模板能同时匹配"计数 0"和"计数 500"、"有红点"和"没红点"。
加载日志会打 `[TPL] btn_battle3.png mask: 1 rect(s), 40% pixels ignored`。

## 同一个按钮可以挂多个模板

游戏里按钮外观会变，**一个按钮对应多个模板**，程序取匹配分最高的那个：

- 「对战」在**每日额外奖励可领**时会多一行小字 → `btn_battle2.png`；
- 新版本加了赛季进度 → `btn_battle3.png`；
- 某些模式的开始按钮变成绿色「加入」→ `btn_join.png`；
- 再加新外观时，把文件放进 `templates/` 并加进 `src/ui_buttons.cpp` 的 `kSpecs`
  （每个按钮最多 5 个外观）。

## 每个按钮的搜索范围

模板只在固定区域内搜（`kSpecs` 里的 `Rect roi`，720×1280 坐标）：

| 按钮 | 搜索范围 |
|---|---|
| 对战 / 加入 | x 210..520, y 900..1120 |
| 确定 | x 255..475, y 1040..1180 |
| 经典1对1 | 全屏（列表会滚动，位置不固定） |
| 当前模式图标 | x 490..670, y 920..1100 |

换分辨率或界面大改时改这里的 `Rect` 即可，不用动匹配算法。

## 裁剪注意

- 模板要比按钮本体**外扩几像素**，保留边框和投影；
- 避开会呼吸的高光/闪光区域，否则同一按钮不同帧的分数会抖；
- 会变的内容别硬裁掉——用 `.mask` 标出来，保住边框和标题这些稳定特征；
- 匹配用归一化相关系数（NCC），阈值：对战/加入 `0.72`、确定 `0.70`、1对1 `0.80`、模式图标 `0.82`。

## 校验

打包前会用 `tools/verify_packages.py` 检查这 9 个文件（7 模板 + 2 掩膜）是否都在包里，
少一个 CI 就会红——避免"到了真机才发现认不出按钮"。
